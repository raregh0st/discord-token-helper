Discord Token Helper

Copy the auth token of the Discord account you are already logged in as. Made by raregh0st.

Never share your token. Anyone with it has full access to your account and can bypass your password and 2FA. Using a token to automate a user account (a "self-bot") violates Discord's Terms of Service and can get your account terminated. Use this only on your own account, at your own risk.

Troubleshooting

It returns undefined or says "No token found"

Make sure you are on discord.com/app and logged in, then reload the page and try again. Discord loads modules lazily.

Clicking the bookmark does nothing

Some browsers strip the javascript: prefix from pasted URLs. Re-add it manually, or use the console method.

The token is wrapped in quotes

Discord stores it as JSON, so both snippets strip the quotes with JSON.parse for you.

It worked before, not anymore

Discord changes its internals regularly. Open an issue on GitHub with your Discord build (web/desktop) and the error.

How it works

Discord is a webpack app. Webpack keeps a global chunk registry called webpackChunkdiscord_app, and pushing a fake chunk into it makes webpack call your callback with a require function:

window.webpackChunkdiscord_app.push([
  [Symbol()],   // fake chunk id
  {},           // no new modules
  (req) => {
    // req.c is the module cache: { [moduleId]: { exports } }
  },
]);

Discord's auth store exports getToken() / setToken(). The snippet walks the module cache, finds the module exposing getToken (sometimes as exports.getToken, sometimes as exports.default.getToken) and calls it. The result is normalized to a string: if getToken() returns an object, its token / value / accessToken field is used, so you get the token itself and never [object Object]. As a fast path it first checks localStorage.getItem("token"), where the web client keeps the same value as a JSON string.

The older bookmarklet that used an <iframe> + document.write broke because it called location.reload() first (unloading the page before the script finished) and because document.write() after load wipes the whole Discord UI. This version renders a normal element on top of the page instead, so nothing is destroyed.
